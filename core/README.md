# core/ — the channel-agnostic engine

Implemented and tested. Every module below ships with tests that fail if its load-bearing
property is removed, and `tests/mutation_check.sh` deletes those properties one at a time to
prove the tests have teeth. This table is itself tested (`tests/test_docs.py`): a row citing
a module that does not exist, or a module that ships without a row here, turns the suite red —
this file listed six phantom modules while omitting the implemented ones before that check
existed (ENH-19).

Import rule for everything in this directory: **no platform imports** — `core/` never imports
a concrete adapter. Adapters are discovered and loaded from configuration (`core/config.py`),
so a new channel type is a directory drop with zero core changes.

| Module | Responsibility |
|---|---|
| `checks.py` | health checks that cannot silently no-op: every check emits PASS or FAIL, a None or junk verdict becomes FAIL, and a PASS that inspected nothing is refused (the incumbent watchdog read "OK" for weeks while checking a field its events never carried) |
| `classify.py` | message classification (EXEC-REQUEST / COMMITMENT-ASK / QUESTION / STATEMENT): word-boundary keyword matching (the incumbent's substring match misfired on 34% of its EXEC-REQUESTs), a commitment ask always outranks a work request, and every decision records the cues that produced it |
| `compose.py` | reply composition with evidence-citation discipline — the origin rule "never improvise a number, cite banked artifacts" made structural: prose may carry no digit-bearing tokens, a claim requires a citation resolving to a banked artifact, every number in the claim must actually occur in the cited evidence (a real citation on an invented figure is refused as laundering), and the citation is rendered into the reply itself so the recipient can check it — the layer between "I want to reply" and the content-blind string `outbox.py` sends |
| `config.py` | build the whole engine from `settings.json` alone: adapter discovery, `env:NAME` credential references (literal credentials refused at load), default-deny reply policy, relative paths resolved against the config directory; the instance name is the tenant-isolation key — duplicates and path-shaped names refused at load, credentials resolved per instance, and `outbox_path_for` derives one outbox file per instance |
| `dashboard.py` | the operator surface's read layer: one severity-ordered attention queue (crashed in-flight sends, answers invalidated by a later edit, drafts at the operator gate, the unanswered backlog) built from the adopter's own journal and per-instance outboxes; read-only by construction (every connection is sqlite `mode=ro`, missing state is reported rather than created, and an absent file reads as unknown, never as zero) — `scripts/dashboard.py` is the Streamlit shell that renders it, loopback-only |
| `doctor.py` | the preflight command (`python3 -m core.doctor --config settings.json`): validates the config, resolves credentials (naming the references, never their values), confirms each configured channel readable with one live poll per instance (cross-checked against the adapter's declared watch set — the two-place footgun), prints the effective reply policy per channel exactly as `outbox.py` resolves it, and refuses to look healthy when it is not — no vacuous pass, no state created |
| `escalate.py` | edge-triggered operator escalation: notify on a state CHANGE, never on a state (a level-triggered once-a-minute probe is 1,440 identical alerts a day); edge state lives in sqlite so every cron-shaped poll sees it; recovery is announced, not just recorded |
| `journal.py` | idempotent audit journal: one row per distinct message however often it is re-seen (the incumbent log held 323 entries for 177 messages), edits detected by content and kept as revisions, classification cues preserved for dispute |
| `outbox.py` | stage-first send discipline and the ONLY caller of `adapter.send()`: durable INTENT → send → read-back VERIFY → COMMIT, so a crash at any seam recovers to exactly-once; staged targets stop at the operator gate; sends paced at ≤1 message/second per channel; reply policy resolvable per placement (thread vs channel, each deny-by-default) with the placement recorded on the row so recovery never resurfaces a thread reply top-level; multi-instance deployments give each instance its OWN outbox file (config's `outbox_path_for`) so recovery can never replay one tenant's row through another tenant's adapter |
| `owed.py` | the owed-work edge: promised-but-unstarted work stays visible, idle backoff can never suppress it (root cause of a measured 8h17m silent stall), and a recorded driver must be provably alive, not just named |
| `parity.py` | shadow-mode parity differ against the incumbent oracle, **classified by cause**: the oracle is an archive that drifts from the platform in both directions (it holds deleted messages; it has its own gaps), so each divergence is placed in a named class — only `ENGINE_LOST` (the platform still serves it, it is inside the window the engine's cursor claims, and the engine lacks it) is a defect, and it is refused from the accept-list so no configuration can waive a real loss; fail-closed wherever the platform is silent (no snapshot ⇒ every miss is a loss; an empty snapshot is an ERROR), and an empty comparison is an ERROR, never a pass |
| `retention.py` | upstream-deletion detection, because the differ ACCEPTS the `UNRETRIEVABLE` class and is therefore blind to it growing: consecutive platform snapshots answer "which rows that we hold were retrievable last time and are not now", each new one gets a durable first-write-wins tombstone (so a persistent deletion is an edge, not a repeating alert), and the engine's own copy is never destroyed — the store is an archive, so a tombstone records that the platform's copy is gone without losing ours; an empty previous snapshot cannot conclude "nothing was deleted" and an empty current one must not be read as a mass deletion, so both raise |
| `ratelimit.py` | per-(instance, method) 429 back-off honouring Retry-After exactly: a read 429 never pauses sends, one workspace's hold never crosses to another, and exhausted retries surface the error instead of dropping the message |
| `schedule.py` | the reference scheduler loop (probe → classify → journal → route → owed) with the incumbent's loop bugs structurally fixed: a single-instance guard per state directory (an OS-held sqlite lock, so a crashed holder leaves no stale lockfile), the cursor committed only after the journal (a crash duplicates, never loses), idle backoff that can never suppress owed work (the measured 8h17m stall), and edge-triggered escalation of unattended work |
| `slo.py` | detection-latency SLO with the completeness poll as ground truth: p50/p90 of push detection latency and of push's lead over the poll, failing on a budget breach or on any poll-confirmed message push never delivered (the incumbent's "12.1min → ~1min" headline only measured its own cron cadence); an empty or unmeasurable comparison is an error, never a pass |
| `store.py` | sqlite message store: explicit pinned schema (unknown and missing fields refused), idempotent re-ingest, first-arrival stamping (first-write-wins, so re-polls never move it), per-(instance, channel) cursor persistence |

Each module's docstring carries the measured incident it exists to prevent — read it before
changing behaviour.
