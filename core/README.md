# core/ — the channel-agnostic engine

Implemented and tested. Every module below ships with tests that fail if its load-bearing
property is removed, and `tests/mutation_check.sh` deletes those properties one at a time to
prove the tests have teeth. This table is itself tested (`tests/test_docs.py`): a row citing
a module that does not exist, or a module that ships without a row here, turns the suite red —
this file listed six phantom modules while omitting the implemented ones before that check
existed (ENH-19).

Import rule for everything in this directory: **no platform imports** — `core/` never imports
a concrete adapter. Adapters are discovered and loaded from configuration (`core/config.py`),
so a new channel type is a directory drop with zero core changes.

| Module | Responsibility |
|---|---|
| `checks.py` | health checks that cannot silently no-op: every check emits PASS or FAIL, a None or junk verdict becomes FAIL, and a PASS that inspected nothing is refused (the incumbent watchdog read "OK" for weeks while checking a field its events never carried) |
| `classify.py` | message classification (EXEC-REQUEST / COMMITMENT-ASK / QUESTION / STATEMENT): word-boundary keyword matching (the incumbent's substring match misfired on 34% of its EXEC-REQUESTs), a commitment ask always outranks a work request, and every decision records the cues that produced it |
| `compose.py` | reply composition with evidence-citation discipline — the origin rule "never improvise a number, cite banked artifacts" made structural: prose may carry no digit-bearing tokens, a claim requires a citation resolving to a banked artifact, every number in the claim must actually occur in the cited evidence (a real citation on an invented figure is refused as laundering), and the citation is rendered into the reply itself so the recipient can check it — the layer between "I want to reply" and the content-blind string `outbox.py` sends |
| `config.py` | build the whole engine from `settings.json` alone: adapter discovery, `env:NAME` credential references (literal credentials refused at load), default-deny reply policy, relative paths resolved against the config directory; the instance name is the tenant-isolation key — duplicates and path-shaped names refused at load, credentials resolved per instance, and `outbox_path_for` derives one outbox file per instance |
| `dashboard.py` | the operator surface's read layer: one severity-ordered attention queue (crashed in-flight sends, answers invalidated by a later edit, drafts at the operator gate, the unanswered backlog) built from the adopter's own journal and per-instance outboxes; read-only by construction (every connection is sqlite `mode=ro`, missing state is reported rather than created, and an absent file reads as unknown, never as zero) — `scripts/dashboard.py` is the Streamlit shell that renders it, loopback-only |
| `doctor.py` | the preflight command (`python3 -m core.doctor --config settings.json`): validates the config, resolves credentials (naming the references, never their values), confirms each configured channel readable with one live poll per instance (cross-checked against the adapter's declared watch set — the two-place footgun), prints the effective reply policy per channel exactly as `outbox.py` resolves it, and refuses to look healthy when it is not — no vacuous pass, no state created |
| `escalate.py` | edge-triggered operator escalation: notify on a state CHANGE, never on a state (a level-triggered once-a-minute probe is 1,440 identical alerts a day); edge state lives in sqlite so every cron-shaped poll sees it; recovery is announced, not just recorded |
| `journal.py` | idempotent audit journal: one row per distinct message however often it is re-seen (the incumbent log held 323 entries for 177 messages), edits detected by content and kept as revisions, classification cues preserved for dispute |
| `outbox.py` | stage-first send discipline and the ONLY caller of `adapter.send()`: durable INTENT → send → read-back VERIFY → COMMIT, so a crash at any seam recovers to exactly-once; staged targets stop at the operator gate; sends paced at ≤1 message/second per channel; reply policy resolvable per placement (thread vs channel, each deny-by-default) with the placement recorded on the row so recovery never resurfaces a thread reply top-level; multi-instance deployments give each instance its OWN outbox file (config's `outbox_path_for`) so recovery can never replay one tenant's row through another tenant's adapter; a thread reply through an adapter that cannot place it (declared `threads: false`, or a `send()` without `thread_id`) is refused before any NEW row is written or claimed — replays of a delivered reply are answered from the row — so it is never flattened and never wedged at the gate (review D1/F5/F9); ENH-31: five refusals before the INTENT flip — the instance's marker (a whole word, never a raw prefix), a pre-send re-read through the adapter's `newest()` against the platform ts the caller's page SHOWED at stage (`seen_ts`, passed by the surface; the platform's newest only for a draft minted without a page): "re-read first" when anything the human has not seen arrived, and staging the same text again advances the baseline exactly to the message the refusal named (`refused_ts`), the adapter's `MAX_TEXT_CHARS`, the BLOCK-tier credential scan (`redact.py`), and the policy re-read at every seam — `stage()`, `release()` and `send()` share one predicate: default deny, exactly `staged`, or `direct` through an adapter declaring it on — then the exact read-back by key and canonical text after the post, with the thread and the approved text passed to adapters that take them (a message carrying the key with other text parks the row as MISMATCH through `delivery.DeliveryMismatch`: never re-sent, never committed); placement is decided with the adapter; `recover()` isolates each row and records failures by key, re-sends a key the platform does not hold at most once per completed run (`resent_at`, recorded with the receipt — and recorded on an ambiguous answer too, since the post may have landed; the re-send is left SENT for the next run to prove), parks as UNPROVEN a row still unproven on that next run, a row whose target is gone (`delivery.TargetGone`) or an unproven earlier post the platform refuses to re-send, hands back a row whose re-send met a refusal the allowlist did not know once absence was proven, retries transient errors without posting or parking (`attempts` counts touches), honours the adapter's send capability, bounds a restart search by the platform ts the human saw, and stops on a 429; a 429 on the click, or a DEFINITE refusal of the post (`delivery.NotPosted`), hands the draft back to where it came from (STAGED, or UNPROVEN for a re-approval), an ambiguous answer leaves the row in flight; `settle(key, delivered)` is the human's terminal action on a MISMATCH or UNPROVEN row (SETTLED, kept, no longer triage; the surface ties the ask when delivered, closes it as not needed otherwise) and `release(reapprove=True)` the human's one more post on an UNPROVEN row, skipping only the re-read that click replaces |
| `owed.py` | the owed-work edge: promised-but-unstarted work stays visible, idle backoff can never suppress it (root cause of a measured 8h17m silent stall), and a recorded driver must be provably alive, not just named |
| `parity.py` | shadow-mode parity differ against the incumbent oracle, **classified by cause**: the oracle is an archive that drifts from the platform in both directions (it holds deleted messages; it has its own gaps), so each divergence is placed in a named class — only `ENGINE_LOST` (the platform still serves it, it is inside the window the engine's cursor claims, and the engine lacks it) is a defect, and it is refused from the accept-list so no configuration can waive a real loss; fail-closed wherever the platform is silent (no snapshot ⇒ every miss is a loss; an empty snapshot is an ERROR), and an empty comparison is an ERROR, never a pass |
| `retention.py` | upstream-deletion detection, because the differ ACCEPTS the `UNRETRIEVABLE` class and is therefore blind to it growing: consecutive platform snapshots answer "which rows that we hold were retrievable last time and are not now", each new one gets a durable first-write-wins tombstone (so a persistent deletion is an edge, not a repeating alert), and the engine's own copy is never destroyed — the store is an archive, so a tombstone records that the platform's copy is gone without losing ours; an empty previous snapshot cannot conclude "nothing was deleted" and an empty current one must not be read as a mass deletion, so both raise |
| `ratelimit.py` | per-(instance, method) 429 back-off honouring Retry-After exactly: a read 429 never pauses sends, one workspace's hold never crosses to another, and exhausted retries surface the error instead of dropping the message |
| `reconfig.py` | staged configuration changes — the ENH-28 trust shape applied to settings.json: an edit op builds a candidate, `stage()` validates it with the engine's OWN loader (the refusal the adopter would otherwise meet at startup) and records the exact old→new diff durably, and only `apply()` — a human click on that exact diff, stale-checked against the file and re-validated against the current environment — writes it (atomically); discard is terminal and kept; policy WIDENINGS are detected and carried on the staged row; auth values are env-var NAME references, with a pasted secret refused unstored and unechoed; a new channel denies by default by OMITTING the policy key, so the loader's own DENY stays the single copy of that rule; there is no hot-reload — `RELOAD_TRUTH` states that a running scheduler/watcher must be restarted |
| `schedule.py` | the reference scheduler loop (probe → classify → journal → route → owed) with the incumbent's loop bugs structurally fixed: a single-instance guard per state directory (an OS-held sqlite lock, so a crashed holder leaves no stale lockfile), the cursor committed only after the journal (a crash duplicates, never loses), idle backoff that can never suppress owed work (the measured 8h17m stall), and edge-triggered escalation of unattended work; one thread-sweep budget per adapter per cycle, charged by attempt (refused fetches too), spent across its channels with one call reserved per waiting channel and the bulk moving to the channel that waited, any channel a cycle skipped (a 429, more channels than calls) swept first next cycle and named with its cause in the summary, window and order durable in the store so `--once` runs keep them (review D2/F1-F4: config order starved every channel behind a backlog, silently; the position-based window can still stick on one ask at capacity — COMMS-79 item 18); ENH-31: the DM answered-state runs per DM channel every cycle, and the source's answerers reach the thread sweep |
| `slo.py` | detection-latency SLO with the completeness poll as ground truth: p50/p90 of push detection latency and of push's lead over the poll, failing on a budget breach or on any poll-confirmed message push never delivered (the incumbent's "12.1min → ~1min" headline only measured its own cron cadence); an empty or unmeasurable comparison is an error, never a pass |
| `delivery.py` | the one exception an adapter's `read_back()` may raise (ENH-31 guard 3): `DeliveryMismatch` — a message carrying this key IS on the platform, but its text is not the approved text; the outbox parks such a row as MISMATCH (never re-sent, never committed) instead of reading it as "never sent" and posting again. Lives apart from `outbox.py` so an adapter can raise it without importing the send layer |
| `redact.py` | the BLOCK-tier credential scan every outgoing payload passes before the outbox lets it leave the host (ENH-31 guard 5): the sanitize gate's credential classes (Slack and app tokens, Telegram bot tokens, AWS access keys, private keys, assigned secrets), built by concatenation so the source never matches itself; names the class hit and never echoes the match; deliberately not the identifier tier, because a reply may name a channel id or a loopback URL |
| `threads.py` | in-thread answers close open asks (ENH-30): each scheduler cycle sweeps the open asks' threads through the adapter's optional `replies()`, stores and returns the new replies for journaling, and ties an ask to the FIRST reply from someone other than the asker (`Journal.mark_responded`, key `thread-reply:<ts>`) — measured on the aws-do-agent integration 2026-10-12, where `responded_at` had no production caller and the Slack adapter polled `conversations.history` only (which never serves a thread reply), so every answered ask read UNANSWERED forever; one budget per adapter per cycle spent across its channels, a window that rotates through the open asks (none starves while the window is wider than the arrival rate — it is a position in the newest-first list, so at ~1 call per cycle with a new ask every cycle it can stick on one ask: COMMS-79 item 18), one call per thread root, a 429 stops that adapter's sweeping for the cycle and is reported, a platform error on one thread is recorded by ask and skipped (never a crash loop), a reply that is itself an ask or comes from an unattributed sender answers nothing, and an adapter without `replies()` yields None (declared absent, never "nothing new"); ENH-31: the source's `answerers` list restricts who may close OTHER people's asks (threads and DMs alike; a bystander's "+1" then closes nothing, while an ask posed by a listed answerer is closed by the other party), the engine's own deliveries — recognised by the metadata the poll stores — are never credited by the sweep or the DM rule, and `close_dm_asks()` is the DM answered-state — in a 1:1 direct message each later top-level message that is an answer closes the most recent still-open ask it can answer (never its own sender's), once, store-only, no platform call, with a non-orderable id space refused by name into the cycle summary |
| `store.py` | sqlite message store: explicit pinned schema (unknown and missing fields refused), idempotent re-ingest, first-arrival stamping (first-write-wins, so re-polls never move it), per-(instance, channel) cursor persistence |

Each module's docstring carries the measured incident it exists to prevent — read it before
changing behaviour.
